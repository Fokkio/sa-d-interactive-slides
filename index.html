บทที่ 1 · พื้นฐาน

มองโลกแบบเชิงวัตถุ คืออะไร

แทนที่จะมองระบบเป็นขั้นตอนยาว ๆ เรามองทุกอย่างเป็น “ของ” (Object) แต่ละชิ้น ของแต่ละชิ้นมี 2 อย่างติดตัวเสมอ คือ ข้อมูลของมัน กับ สิ่งที่มันทำได้ เช่น หนังสือเล่มหนึ่งมีชื่อ ราคา และทำได้คือถูกยืม ถูกคืน ส่วนนักเรียนคนหนึ่งมีรหัส ชื่อ และทำได้คือลงทะเบียนเรียน

ของจริง (Object) กับ แบบพิมพ์ (Class) ต่างกันอย่างไร

แบบพิมพ์ คือต้นแบบที่บอกว่าของชนิดนี้ต้องมีข้อมูลอะไร ทำอะไรได้บ้าง ส่วนของจริง คือชิ้นที่สร้างจากแบบพิมพ์นั้น เช่น แบบพิมพ์ “นักเรียน” กับนักเรียนชื่อสมชาย รหัส 123 คือของจริง — 2 อย่างนี้อย่าสลับกันตอบ

ของ 1 ชิ้น มีอะไรบ้าง

① ตัวตน คือสิ่งที่ทำให้แยกชิ้นนี้ออกจากชิ้นอื่น ② ข้อมูลหรือสถานะ ③ การกระทำหรือพฤติกรรม

ของในโลกจริงแบ่งได้ 2 แบบ: ของที่จับต้องได้ เช่น หนังสือ รถ กับของที่เป็นแนวคิด เช่น บัญชี การลงทะเบียน

เขียนโปรแกรมแบบเก่า vs แบบเชิงวัตถุ

แบบเก่าแยกข้อมูลออกจากฟังก์ชันที่จัดการข้อมูลนั้น ส่วนแบบเชิงวัตถุเอาข้อมูลกับวิธีจัดการใส่ไว้ในของชิ้นเดียวกัน ข้อดีที่สไลด์เน้น 2 อย่าง: ขยายได้ง่าย เพิ่มชนิดใหม่ไม่ต้องรื้อของเก่าทั้งระบบ และ แบ่งงานเป็นชิ้นเล็ก ๆ ออกแบบและดูแลทีละส่วนได้ง่าย

SA&D กับ OOAD ต่างกันอย่างไร

SA&D มองระบบเป็นขั้นตอนกับข้อมูลที่ไหล ส่วน OOAD มองระบบเป็นของแต่ละชิ้นที่มีข้อมูลกับการกระทำ

แผนภาพมี 2 กลุ่มใหญ่: กลุ่มโครงสร้าง บอกว่าระบบประกอบด้วยอะไร เชื่อมกันอย่างไร (เช่น Class Diagram) · กลุ่มพฤติกรรม บอกว่าระบบทำอะไรและทำตามลำดับอย่างไร (เช่น Use Case, DFD)

ข้อกำหนดของระบบที่ดี ต้อง ครบถ้วน คือไม่มีหน้าที่หายไป และ ไม่ขัดกันเอง คือคำอธิบายแต่ละจุดไม่แย้งกัน
บทที่ 1 · พื้นฐาน

4 คุณสมบัติที่ข้อสอบถามบ่อย — กดพลิกการ์ดเพื่อทายก่อน

ใครมองเห็นข้อมูลข้างในได้บ้าง (Visibility)

เปิดเฉพาะข้างในของตัวเอง (private): คนอื่นห้ามแก้ตรง ๆ ต้องผ่านวิธีที่เตรียมไว้ เช่น ตัวนับจำนวนผู้อ่านห้ามแก้ตัวเลขตรง ๆ ต้องเรียกวิธีเพิ่ม/ลด · เปิดให้ลูกหลานด้วย (protected): แบบที่สืบทอดมาเห็นได้ แต่คนนอกยังเห็นไม่ได้ · เปิดให้ทุกคน (public): ใครก็เรียกใช้ได้

ขั้นตอนจัดกลุ่มของ 3 ขั้น

① กำหนดขอบเขตที่สนใจก่อนว่ากำลังพูดถึงเรื่องอะไร ② หาว่าในขอบเขตนั้นมีของหรือแบบอะไรบ้าง ③ กำหนดว่าแต่ละแบบมีข้อมูลอะไรและการกระทำอะไรบ้าง ถ้าข้ามขั้นแรกจะหลงเอาของที่ไม่เกี่ยวกับระบบเข้ามาด้วย · ชื่อแบบต้องเป็น คำนาม ชื่อการกระทำต้องเป็น คำกริยา

บทที่ 1 · DFD

แผนภาพข้อมูลไหล (DFD) คือแผนที่ของข้อมูล

แผนภาพนี้ไม่ได้บอกขั้นตอนทีละขั้นแบบโปรแกรม แต่บอกว่า ข้อมูลเริ่มจากใคร ไหลไปไหน และไปเก็บที่ไหน มีสัญลักษณ์แค่ 4 อย่างเท่านั้น — รูปทรงตามสไลด์ต้นฉบับ (ไฟล์ 1.pdf รูปที่ 3.2–3.6) เป๊ะ ๆ

ซ้าย: คนข้างนอก = สี่เหลี่ยมธรรมดา · กลาง: ขั้นตอนทำงาน = สี่เหลี่ยมมุมมน แบ่ง 2 ช่อง (บน = เลขขั้นตอน, ล่าง = ชื่อ กริยา+กรรม) · ขวา: แฟ้มข้อมูล = สี่เหลี่ยมเปิดด้านขวา (ซ้าย = รหัส D, ขวา = ชื่อแฟ้ม) · ลูกศร = ชื่อข้อมูลที่ไหล

คนหรือระบบข้างนอก (External Entity)

สี่เหลี่ยมธรรมดา คือคนที่ส่งข้อมูลเข้ามาหรือรับข้อมูลออกไป เช่น ลูกค้า พนักงาน ของพวกนี้อยู่นอกระบบที่เราสนใจ

ขั้นตอนทำงาน (Process)

สี่เหลี่ยมมุมมนแบ่งครึ่ง ช่องบนใส่เลขขั้นตอน ช่องล่างใส่ชื่อ ชื่อต้องเป็นคำกริยา + สิ่งที่ทำ เช่น ค้นหาข้อมูลสินค้า ลบข้อมูลสินค้า เลขกำกับเช่น 3.5, 4.3

ลูกศรข้อมูล (Data Flow)

เส้นที่บอกว่าข้อมูลอะไรไหลไปทางไหน ชื่อต้องเป็นชื่อข้อมูล ไม่ใช่ชื่อการกระทำลอย ๆ

ที่เก็บข้อมูล (Data Store)

สี่เหลี่ยมเปิดด้านขวา ช่องซ้ายใส่รหัสแฟ้ม เช่น D3, D4 ช่องขวาใส่ชื่อแฟ้ม เช่น แฟ้มข้อมูลสินค้า ด้านขวาไม่มีเส้นปิด

บทที่ 1 · DFD

กฎเหล็ก DFD 3 ข้อ + ระดับของแผนภาพ

กฎ 3 ข้อที่ห้ามลืมเด็ดขาด
  1. ข้อมูลห้ามวิ่งตรงจากคนข้างนอกไปแฟ้ม หรือจากแฟ้มไปคนข้างนอก หรือจากแฟ้มไปแฟ้ม ต้องผ่านขั้นตอนทำงานเสมอ
  2. ขั้นตอนทำงานต้องมีทั้งข้อมูลเข้าและข้อมูลออก จะรับอย่างเดียวแล้วจบ หรือสร้างข้อมูลจากอากาศไม่ได้
  3. ถ้าแฟ้มหนึ่งไม่มีข้อมูลที่เราต้องการครบ ต้องไปอ่านอีกแฟ้มหนึ่งมาต่อให้ครบ — นี่คือหัวใจของข้อค้นหาสินค้า

ระดับของแผนภาพ

ระดับบริบท (Context): ระบบทั้งระบบเป็นก้อนเดียว มีแค่คนข้างนอกกับลูกศรเข้าออก
ระดับ 1: แตกก้อนใหญ่ออกเป็นขั้นตอนหลัก
ระดับ 2: แตกขั้นตอนหลักแต่ละตัวออกเป็นขั้นตอนย่อยอีกชั้นหนึ่ง

ความสมดุล (Balancing)

ข้อมูลที่เข้าและออกของขั้นตอนใหญ่ ต้องตรงกับข้อมูลที่เข้าและออกของขั้นตอนย่อยที่แตกออกมาจากมัน ถ้าขั้นตอนใหญ่รับข้อมูล A แล้วส่ง B ออก ขั้นตอนย่อยข้างในรวมกันก็ต้องรับ A แล้วส่ง B เท่านั้น

กับดักข้อสอบ: แผนภาพนี้ ไม่มีสัญลักษณ์ตัดสินใจ ไม่มีวนซ้ำ และไม่มีลำดับเวลา ถ้าโจทย์ถามว่า “ขั้นตอนที่ 1 2 3 คืออะไร” คำตอบที่ถูกไม่ใช่แผนภาพนี้ แต่เป็นแผนภาพขั้นตอนหรือแผนภาพกิจกรรม
บทที่ 1 · พจนานุกรมข้อมูล

พจนานุกรมข้อมูล (Data Dictionary) คือสมุดอธิบายข้อมูล

สมุดเล่มนี้อธิบายว่า ข้อมูลแต่ละอย่างคืออะไร ประกอบด้วยอะไรบ้าง ใช้สัญลักษณ์สั้น ๆ 4 ตัว — กดพลิกการ์ดเพื่อฝึกอ่าน

ตัวอย่างที่ต้องเขียนให้ได้

ข้อมูลสินค้า = รหัสสินค้า + ชื่อสินค้า + จำนวนสินค้า + รหัสประเภทสินค้า · ผลการค้นหา = รหัสสินค้า + ชื่อสินค้า + จำนวนสินค้า + ชื่อประเภทสินค้า · เงื่อนไขค้นหา = [ชื่อสินค้า | ชื่อประเภทสินค้า] · ข้อมูลก่อนลบ = รหัสสินค้า + ชื่อสินค้า + จำนวนสินค้า + รหัสประเภทสินค้า + ชื่อประเภทสินค้า

บทที่ 1 · เฉลยข้อสอบ

เฉลยข้อ 3.5 ค้นหาข้อมูลสินค้า — ทำไมต้องอ่าน 2 แฟ้ม

โจทย์พูดง่าย ๆ: ลูกค้ากับพนักงานพิมพ์ชื่อสินค้า หรือชื่อประเภทสินค้า แล้วระบบต้องโชว์รหัสสินค้า ชื่อสินค้า จำนวนสินค้า และชื่อประเภทสินค้า
แฟ้มที่ให้มา: D3 แฟ้มประเภทสินค้า = รหัสประเภท + ชื่อประเภท · D4 แฟ้มสินค้า = รหัสสินค้า + ชื่อสินค้า + จำนวนสินค้า + รหัสประเภทสินค้า
จุดสำคัญ: แฟ้มสินค้าเก็บแค่ "รหัส" ประเภท ไม่ได้เก็บ "ชื่อ" ประเภทไว้ด้วย อ่านแค่แฟ้มสินค้าอย่างเดียวจะไม่รู้ชื่อประเภท ต้องเอารหัสประเภทไปเปิดแฟ้มประเภทอีกครั้งเพื่อแปลรหัสเป็นชื่อ

DFD ข้อ 3.5 — ลูกค้าและพนักงานแยกคนละกล่อง, ขั้นตอน 3.5 อยู่กลาง, แฟ้ม D4 (สินค้า) อยู่บน D3 (ประเภท) อยู่ล่าง
1ลูกค้ากับพนักงานแยกเป็นกล่องคนละกล่อง เพราะเป็นคนข้างนอกคนละตัวกัน ถึงแม้จะค้นแบบเดียวกันก็ตาม
2ระบบไปอ่านแฟ้มสินค้า (D4) ได้รหัส ชื่อ จำนวน และรหัสประเภท
3เอารหัสประเภทไปอ่านแฟ้มประเภท (D3) ได้ชื่อประเภท
4ส่งผลการค้นหาทั้ง 4 อย่างกลับไปให้ผู้ใช้คนนั้น
5ถ้าค้นด้วยชื่อประเภท: แผนภาพนี้ไม่วาดเงื่อนไขตัดสินใจ เพราะ DFD ไม่มีสัญลักษณ์ตัดสินใจ หลักการข้างในขั้นตอนคือ ถ้าค้นด้วยชื่อประเภท ให้เริ่มที่แฟ้มประเภทก่อนเพื่อหารหัสประเภท แล้วค่อยไปค้นแฟ้มสินค้าด้วยรหัสนั้น
บทที่ 1 · เฉลยข้อสอบ

เฉลยข้อ 4.3 ลบข้อมูลสินค้า — ลบทั้งทีต้องโชว์ก่อน

โจทย์พูดง่าย ๆ: พนักงานเท่านั้นที่ลบได้ และก่อนลบระบบต้องโชว์ข้อมูลให้พนักงานเห็นก่อน 5 อย่าง คือรหัสสินค้า ชื่อสินค้า จำนวนสินค้า รหัสประเภทสินค้า และชื่อประเภทสินค้า

ระวัง: ข้อนี้เลขแฟ้มสลับกับข้อ 3.5 คือ D3 กลายเป็นแฟ้มสินค้า และ D4 กลายเป็นแฟ้มประเภทสินค้า ต้องเขียนตามโจทย์ข้อนั้น ๆ อย่าท่องจำว่า D3 คืออะไรตายตัว
DFD ข้อ 4.3 — พนักงานคนเดียว, แฟ้ม D3 = สินค้า (บน), D4 = ประเภท (ล่าง) สลับกับข้อ 3.5
1พนักงานบอกรหัสสินค้าที่จะลบ
2ระบบอ่านแฟ้มสินค้าได้ 4 อย่าง (รหัส ชื่อ จำนวน รหัสประเภท)
3เอารหัสประเภทไปอ่านแฟ้มประเภท ได้ชื่อประเภท
4โชว์ข้อมูลทั้ง 5 อย่างให้พนักงานตรวจ
5พนักงานส่งคำยืนยันการลบ
6ระบบลบออกจากแฟ้มสินค้าเท่านั้น — ห้ามลบแฟ้มประเภทด้วย เพราะประเภทนั้นยังใช้กับสินค้าอื่นได้
7ลูกศรไปแฟ้มสินค้า: เส้นนี้ส่งรหัสสินค้าไปค้นหาก่อน และหลังยืนยันแล้วใช้รหัสเดียวกันสั่งลบ วาดเป็นเส้นเดียวได้เพราะข้อมูลและทิศเดียวกัน ชื่อลูกศรจึงเป็นชื่อข้อมูล ไม่ใช่ชื่อการกระทำ
บทที่ 1 · DFD

วิธีวาด DFD ในห้องสอบ 5 ขั้น

  1. เขียนคนข้างนอกก่อนว่ากี่คน
  2. เขียนกล่องขั้นตอนตรงกลาง พร้อมชื่อและเลขตามโจทย์
  3. เขียนแฟ้มตามเลข D ในโจทย์ข้อนั้น พร้อมเขียนกำกับว่าแฟ้มนั้นเก็บอะไรบ้าง
  4. วาดลูกศรข้อมูลเข้าก่อน แล้วค่อยวาดลูกศรไปอ่านแฟ้มและลูกศรส่งผลกลับ
  5. ตรวจ 3 อย่าง: ทุกขั้นตอนมีทั้งเข้าและออกไหม · ลูกศรทุกเส้นมีชื่อกำกับไหม · ไม่มีลูกศรวิ่งตรงจากแฟ้มไปหาคนข้างนอกไหม
ท่องก่อนเข้าห้องสอบ: “คนข้างนอกห้ามคุยกับแฟ้มตรง ๆ ทุกอย่างต้องผ่านขั้นตอน” และ “ชื่อลูกศร = ชื่อข้อมูล ไม่ใช่ชื่อการกระทำ” — 2 ประโยคนี้กันคะแนนหายได้เยอะที่สุดในข้อ DFD

เช็กตัวเองเร็ว ๆ

จริงหรือเท็จ: ลูกศรข้อมูลวาดจากแฟ้มข้อมูลตรงไปหาลูกค้าได้ ถ้าลูกค้าเป็นคนขอข้อมูลนั้นเอง

เท็จ — ข้อมูลห้ามวิ่งตรงจากแฟ้มไปคนข้างนอก ต้องผ่านขั้นตอนทำงานเสมอ (กฎข้อ 1)

จริงหรือเท็จ: DFD บอกได้ว่าขั้นตอนไหนทำก่อน–หลัง และตัดสินใจเลือกทางไหน

เท็จ — DFD ไม่มีสัญลักษณ์ตัดสินใจ ไม่มีวนซ้ำ ไม่มีลำดับเวลา บอกแค่ว่าข้อมูลไหลจากใครไปไหนและเก็บที่ไหน
บทที่ 2 · Use Case

แผนภาพหน้าที่ของระบบ (Use Case Diagram) คืออะไร

รูปนี้ตอบคำถามเดียวว่า ระบบนี้ทำหน้าที่อะไรบ้าง และใครใช้หน้าที่ไหน ไม่ได้บอกขั้นตอนข้างใน คนที่ใช้ระบบเรียกว่า ผู้ใช้ภายนอก (Actor) อยู่นอกกรอบระบบเสมอ ส่วนหน้าที่ของระบบ (Use Case) อยู่ในกรอบ ชื่อหน้าที่ต้องเป็นคำกริยา + สิ่งที่ทำ เช่น ถอนเงิน โอนเงิน

เส้นตรงธรรมดา (Association)

ผู้ใช้คนนั้นใช้หน้าที่นั้นได้ เส้นระหว่างผู้ใช้กับหน้าที่เป็นเส้นตรงธรรมดา ไม่มีหัวลูกศร

<<include>> — ต้องทำทุกครั้ง

เส้นประเขียนว่า include แปลว่า ขาดไม่ได้ เช่น ถอนเงินกับโอนเงินต้องยืนยันตัวตนทุกครั้ง ลูกศรชี้ จากหน้าที่หลักไปหาหน้าที่ที่ถูกเรียกใช้

<<extend>> — ทำบางครั้ง

เส้นประเขียนว่า extend แปลว่า ทำเมื่อมีเงื่อนไขเท่านั้น เช่น กดยกเลิกถึงจะเกิดการยกเลิกรายการ ลูกศรชี้ จากหน้าที่เสริมไปหาหน้าที่หลัก (ทิศตรงข้ามกับ include)

ลูกศรหัวสามเหลี่ยมโปร่ง (Generalization)

แปลว่าแบบย่อยของแบบใหญ่ เช่น ลูกค้าทั่วไปกับสมาชิก เป็นแบบย่อยของลูกค้า ลูกศรชี้จากลูกไปหาแม่ ใช้ได้ทั้งกับผู้ใช้และหน้าที่

ข้อห้ามที่เจอบ่อย

อย่าวาดตัวระบบเองเป็นผู้ใช้ เช่น อย่าวาดตู้เอทีเอ็มเป็นคนข้างนอก เพราะตู้คือกรอบระบบเอง และหน้าที่ที่ถูก include ไม่ต้องมีเส้นตรงจากผู้ใช้ไปหาโดยตรง

ขั้นตอนสร้างแผนภาพ

① หาผู้ใช้ตามบทบาทที่ต่างกัน ② หาหน้าที่แต่ละอย่าง ③ หาความสัมพันธ์ระหว่างหน้าที่ · ผู้ใช้ที่เป็นคนให้วาดเป็นรูปคน ถ้าไม่ใช่คนให้วาดเป็นสี่เหลี่ยมพร้อมคำกำกับ <<actor>>

แบบประกอบกัน (Aggregation) — เพชรโปร่ง

ของใหญ่เกิดจากของย่อยมารวมกัน แต่ของย่อยยังอยู่ได้ถ้าของใหญ่หายไป เช่น ห้องเรียนยุบไป นักเรียนก็ยังเป็นนักเรียนอยู่

แบบผูกชีวิต (Composition) — เพชรทึบ

เป็นแบบประกอบกันชนิดพิเศษที่ของย่อยอยู่ไม่ได้ถ้าของใหญ่หายไป เช่น หนังสือหายไป ปก คำนำ สารบัญ และเนื้อเรื่องก็หายไปด้วย

เรื่องคลาสที่เหลือ — กล่องคลาส ตัวสร้าง สัญญา

กล่องคลาสแบ่ง 3 ช่อง

บน = ชื่อคลาส, กลาง = ข้อมูล, ล่าง = การกระทำ · ชื่อคลาสเป็นคำนามขึ้นต้นตัวใหญ่, ชื่อข้อมูลและการกระทำขึ้นต้นตัวเล็ก, การกระทำเป็นคำกริยา

บทบาท คือชื่อที่เรียกคลาสในความสัมพันธ์นั้น · ชื่อความสัมพันธ์ บอกว่าความสัมพันธ์นั้นคืออะไร · ทิศทาง บอกว่าอ่านจากฝั่งไหนไปฝั่งไหน

เมธอดตั้งค่าเริ่มต้น (Constructor)

ชื่อเดียวกับคลาส ไม่มีชนิดผลลัพธ์ ใช้กำหนดค่าเริ่มต้น และมีได้หลายตัว · เช่น ApplicationForm มีตัวสร้าง 2 ตัว คือแบบไม่มีข้อมูลเข้า กับแบบมีข้อมูลเข้า · เมธอดทำลายของ (Destructor) จะทำลายของลูกพร้อมแม่ถ้าเป็นแบบผูกชีวิต

สัญญา (Interface) กับคลาสนามธรรม

สัญญาคือสิ่งที่บอกว่าคลาสที่รับไปต้องทำหน้าที่อะไรบ้างให้ครบ · IVehicle มี stop() กับ refuel() คลาสที่รับไปต้องทำครบ รถกับเครื่องบินเติมน้ำมันต่างกัน · LivingThings มี species, grow(), breed() สร้างของตรงไม่ได้ ลูกคือ Animal กับ Plant

กฎของแบบย่อย (Generalization Set)

แบบใหญ่มีลูกครบทุกตัว = ครบ (complete), ยังไม่ครบ = ไม่ครบ (incomplete) · ลูกไม่ทับกัน = แยกกัน (disjoint), ทับกันได้ = ทับกันได้ (overlapping) รวมกันเป็น 4 แบบ แต่ถ้าแบบใหญ่มีลูกแค่ตัวเดียวไม่ต้องระบุข้อนี้

วิธีสร้างแผนภาพคลาสตามสไลด์: หาคลาสธุรกิจจากทุกหน้าที่ให้ครบก่อนเป็น System Vocabulary แล้วจัดกลุ่ม เพิ่มความสัมพันธ์ และเพิ่มข้อมูลธุรกิจ เช่น ค่าปรับที่เชื่อมกับการคืนหนังสือ · สัญญา Itransaction เป็นสัญญาของความสัมพันธ์ระหว่างหนังสือกับลูกค้า คลาสที่ทำตามสัญญานี้คือรายการซื้อ รายการยืม และรายการคืนหนังสือ

Inheritance 4 แบบ — ตัวอย่างจากคลิป

จำให้แม่น: แบบ ครบ (Complete) แบบใหญ่เป็นแบบที่สร้างของตรงไม่ได้ (abstract class) เพราะต้องสร้างจากลูกเท่านั้น · แบบ ไม่ครบ (Incomplete) แบบใหญ่เป็นคลาสปกติ สร้างของได้ · ถ้าแบบใหญ่มีลูกแค่ตัวเดียว ไม่ต้องระบุข้อนี้ · เครื่องหมาย * = แบบใหญ่สร้างของตรงไม่ได้ (abstract)
{complete, overlapping}: นักเรียนทุกคนต้องอยู่ชมรมใดชมรมหนึ่ง หรืออยู่ทั้งสองชมรมก็ได้ ไม่มีใครไม่อยู่ชมรมเลย
{complete, disjoint}: นักเรียนทุกคนต้องเรียนภาษาใดภาษาหนึ่งเท่านั้น เรียนทั้งสองอย่างพร้อมกันไม่ได้
{incomplete, disjoint}: นักเรียนอยู่ชมรมฟุตบอล หรือชมรมดนตรี หรือไม่อยู่ชมรมไหนเลยก็ได้ แบบใหญ่จึงเป็นคลาสปกติ
{incomplete, overlapping}: นักเรียนชายบางคนเป็นหัวหน้าห้อง หัวหน้าห้องบางคนไม่ใช่นักเรียนชาย และมีนักเรียนอีกหลายคนที่ไม่ใช่ทั้งสองอย่าง

ความสัมพันธ์แบบพึ่งพา (Dependency) — <<use>> <<bind>> <<derive>>

ปุ่มกดพึ่งพารูปภาพกับปุ่มลัด ถ้าสิ่งที่พึ่งพาเปลี่ยน ปุ่มก็อาจเปลี่ยนตาม ลูกศร Dependency เป็น เส้นประชี้ไปหาคลาสเป้าหมาย เสมอ

บน: Button พึ่ง Image กับ ShortcutKey ด้วย <<use>> · ล่าง: ตัวอย่าง <<derive>> ระหว่างคลาสต้นทางกับคลาสเป้าหมาย

<<use>>

คลาสเป้าหมายเป็น parameter ของคลาสต้นทาง เช่น Button ใช้ Image กับ ShortcutKey เป็น parameter ถ้าเป้าหมายเปลี่ยน ต้นทางอาจเปลี่ยนตาม · จำ: use = เอามาใช้

<<derive>>

attribute ของคลาสต้นทาง ได้จากการคำนวณค่าบางอย่างในคลาสเป้าหมาย ถ้าค่าต้นฉบับเปลี่ยน ค่าที่คำนวณก็เปลี่ยนตาม · จำ: derive = คำนวณมาจาก

<<bind>>

การผูกค่าจริงเข้ากับคลาสต้นแบบ เช่น รูปภาพกับปุ่มลัดผูกกับปุ่มกด (Button) เป็นความสัมพันธ์แบบพึ่งพาอีกแบบที่สไลด์ระบุชื่อไว้

2. Application ปิดแล้ว Application Form เป็นยังไง? เรียกว่าอะไร?

เฉลย: ปิดตามไปด้วย เรียกว่า Composition (เพชรทึบ ผูกชีวิตกัน)

3. นักเรียนทุกคนต้องเรียนเยอรมันหรืออังกฤษอย่างใดอย่างหนึ่งเท่านั้น คือ Inheritance แบบไหน?

เฉลย: {complete, disjoint} — ครบทุกคน (complete) และห้ามอยู่ทั้งสองอย่าง (disjoint)

4. ถ้าเป็น Complete แล้วสร้าง object จาก superclass ตรง ๆ ได้ไหม? เพราะอะไร?

เฉลย: ไม่ได้ เพราะ superclass เป็น abstract class ต้องสร้างจาก subclass เท่านั้น

5. target class เป็น parameter ของ source class คือ <<use>> หรือ <<derive>>?

เฉลย: <<use>> — ส่วน <<derive>> คือ attribute ที่คำนวณมาจากค่าอื่น

6. ข้อ 3.5 กับ 4.3 เลขแฟ้ม D3/D4 เหมือนกันไหม?

เฉลย: ไม่เหมือน — สลับกัน! 3.5: D3 = ประเภท, D4 = สินค้า · 4.3: D3 = สินค้า, D4 = ประเภท ต้องดูตามโจทย์ข้อนั้น ๆ

7. ลูกศร <<include>> กับ <<extend>> ชี้ไปทางไหน ต่างกันยังไง?

เฉลย: include ชี้จากหน้าที่หลัก → หน้าที่ที่ถูกเรียกใช้ (ทำทุกครั้ง) · extend ชี้จากหน้าที่เสริม → หน้าที่หลัก (ทำบางครั้งเมื่อมีเงื่อนไข) ทิศตรงข้ามกัน

8. สมาชิก 1 คนเช่ารถได้กี่คัน และรถ 1 คันมีคนขับประจำได้กี่คน?

เฉลย: สมาชิกเช่ารถได้ 1..2 คันต่อการเช่า 1 ครั้ง · รถ 1 คันมีคนขับประจำ 0..3 คน (ไม่มีเลยก็ได้)

9. ใน DFD สัญลักษณ์ขั้นตอนทำงานกับแฟ้มข้อมูลต่างกันตรงไหน?

เฉลย: ขั้นตอน = สี่เหลี่ยมมุมมนแบ่ง 2 ช่อง (เลขขั้นตอน + ชื่อ) · แฟ้ม = สี่เหลี่ยมเปิดด้านขวา (รหัส D + ชื่อแฟ้ม) ห้ามวาดสลับกัน

10. UC003 ปรับเกรด ต่างจาก UC001 ลงทะเบียนปกติตรงไหน?
